# UXIM 103.179.45.220 攻击手法与修复对照

## 攻击时间线（摘要）

| 阶段 | 时间（+0800） | 行为 |
|------|----------------|------|
| 侦察 | 2026-09-20 傍晚 | `ffuf`/浏览器扫 `/actuator`、`/.env`、`/phpinfo`、`/config.json` |
| 认证突破 | 09-20 晚～09-22 晨 | `POST /login`（`in=1`）撞库/弱口令；**管理账号未开 2FA** |
| 批量注册 | 全程 | `POST /auth/register` 无 IP 限流（2026-08-22 曾关闭）；邀请码暴力猜解 |
| 后台滥用 | 09-21 中午起 | `GET /admin/users?limit=1000`、聊天记录接口遍历 |
| 写操作探测 | 09-21 | `PUT /admin/users/{id}` 改 `status`/密码；路径 `../` 探测 |

## 根因（按优先级）

1. **管理端无强制 2FA** → 超管/商户密码一旦泄露即获得后台 Token。  
2. **注册无 IP 限流 + 邀请码无格式校验** → 批量注册与探测账号。  
3. **聊天记录 IDOR**：`chatHistory` 只校验「能否看用户 A」，**未校验 A 与 B 是否为好友/同群**，可对 `friend_id=1..N` 批量拉会话。  
4. **`checkAccess` 好友例外** → 管理员与目标互为好友即可扩大可见用户面。  
5. **业务失败仍 HTTP 200** → 自动化工具难以区分成败（日志侧 200 次数膨胀）。  
6. **`limit=1000`** → 单次导出大量用户元数据（已限 100）。  
7. **改密不吊销 JWT** → 会话持续有效直至过期。

## 修复项（`patch-attack-remediation-v2.py`）

- 管理路由：账号必须已启用 2FA；接口级速率限制。  
- `chatHistory`：私聊需好友关系、群聊需群成员；拒绝非法 `room_id`/编码注入。  
- `checkAccess`：移除「互为好友即可看任意用户资料」例外。  
- 管理改密：`JwtService::clearCurrentJti` 全端下线。  
- 管理登录：`in=1` 单独更严 IP 限流；`login2fa` 错误信息脱敏。  
- `BlockedIp`：拦截 `%2e%2e` 等编码路径穿越。  
- Nginx：`/login`、`/register` 限速（可选）。
